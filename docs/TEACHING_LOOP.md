# 教材を学習者に適合させる運用ループ

## 1サイクル

```text
教材を読む・解く
  -> learning-log.md に観察と質問を残す
  -> Codexがフィードバックを分類する
  -> PROFILE.md と ROADMAP.md の更新要否を判断する
  -> 本文・演習・用語集を改訂する
  -> 変更理由と次回の確認点を learning-log.md に記録する
```

## フィードバックの分類

| 種別 | 例 | 主な反映先 |
| --- | --- | --- |
| 表現 | 記法が一貫しない、記号が未定義 | 教材本文・用語集 |
| 足場 | 前提や途中の論理が飛ぶ | 教材本文・演習 |
| 理解 | 概念間の関係が説明できない | 教材順序・ロードマップ |
| 演習 | 問いが曖昧、答案形式が合わない | 演習ノートブック |
| 学習特性 | 同じ種類の説明を継続して好む／苦手とする | PROFILE.md |
| 範囲 | 今すぐ必要ではないが気になる | ROADMAP.md の予告・保留項目 |

## 反映判断

- **本文を直す**：誤解を生む、記号が未定義、導出に必要な説明が欠ける場合。
- **演習を直す**：何を答えるべきか不明、段階的な確認が不足する場合。
- **プロフィールを直す**：複数回のログで再現する学習上の好み・必要な足場が確認された場合。
- **ロードマップを直す**：学習順序、到達条件、優先テーマが変わる場合。
- **保留する**：一回限りの疑問、または先のPhaseで自然に解決される疑問。ただし、いつ扱うかをログに記す。

## 改訂時のチェックリスト

- フィードバックのどの項目を反映したか。
- 反映先は本文、演習、用語集、プロフィール、ロードマップのどれか。
- 新しい記号・用語に型・定義・導線があるか。
- 数式の仮定と破綻条件が明記されているか。
- 演習が記述・計算・コードを一つのノートブックで提出できるか。
- 次回、改善が効いたかを確認する質問は何か。

## このリポジトリでの役割分担

- `PROFILE.md`：安定した学習特性と設計原則。
- `ROADMAP.md`：学習順序・到達条件・現在地。
- `learning-log.md`：日付ごとの生の感想、疑問、回答、改訂記録。
- `texts/`：読解用の教材本文。
- `glossary.md`：教材から参照する用語の短い定義と、必要に応じた深掘り先。
- `notebooks/`：答案欄・コードセル・記述回答を一体化した演習提出物。
