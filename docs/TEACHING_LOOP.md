# 教材を学習者に適合させる運用ループ

## 1サイクル

```text
新しいPhase・Partの初稿作成前にブランチを作る
  -> 初稿を作成・検証し、学習者へ提示する
  -> 学習者がレビュー完了または演習開始を伝えたら初稿をコミットする
教材を読む・解く
  -> docs/<part>/learning-log.md に観察と質問を残す
  -> 学習者が解答・ログの記録完了を伝える
  -> エージェント(Codex/Claude Code)が提出状態を先にコミットする
  -> エージェントがフィードバックを分類する
  -> PROFILE.md と ROADMAP.md の更新要否を判断する
  -> 本文・演習・用語集を改訂する
  -> 変更理由と次回の確認点を docs/<part>/learning-log.md に記録する
  -> 再提出があれば、学習者の修正完了連絡後に先にコミットしてから確認する
  -> Phase完了なら完了作業を済ませ、差分を学習者へ提示する
  -> 学習者の差分確認後にコミット・push・PR作成を行う
```

操作条件の正本は [AGENTS.md](../AGENTS.md#ブランチコミットpushprのタイミング)。このフローはその要約であり、採点・レビュー前に提出状態を保存することと、Phase完了時の差分確認を省略しない。

## フィードバックの分類

| 種別 | 例 | 主な反映先 |
| --- | --- | --- |
| 表現 | 記法が一貫しない、記号が未定義 | 教材本文・用語集 |
| 足場 | 前提や途中の論理が飛ぶ | 教材本文・演習 |
| 理解 | 概念間の関係が説明できない | 教材順序・ロードマップ |
| 演習 | 問いが曖昧、答案形式が合わない | 演習ノートブック |
| 学習特性 | 同じ種類の説明を継続して好む／苦手とする | PROFILE.md |
| 範囲 | 今すぐ必要ではないが気になる | ROADMAP.md の予告・保留項目 |

## 反映判断

- **本文を直す**：誤解を生む、記号が未定義、導出に必要な説明が欠ける場合。
- **演習を直す**：何を答えるべきか不明、段階的な確認が不足する場合。
- **プロフィールを直す**：複数回のログで再現する学習上の好み・必要な足場が確認された場合。
- **ロードマップを直す**：学習順序、到達条件、優先テーマが変わる場合。
- **保留する**：一回限りの疑問、または先のPhaseで自然に解決される疑問。ただし、いつ扱うかをログに記す。

## 改訂時のチェックリスト

- フィードバックのどの項目を反映したか。
- 反映先は本文、演習、用語集、プロフィール、ロードマップのどれか。
- 新しい記号・用語に型・定義・導線があるか。
- 数式の仮定と破綻条件が明記されているか。
- 演習が記述・計算・コードを一つのノートブックで提出できるか。
- 次回、改善が効いたかを確認する質問は何か。

## このリポジトリでの役割分担

- `PROFILE.md`：安定した学習特性と設計原則。
- `docs/ROADMAP.md`：Partの一覧と全体の学習順序。
- `docs/learning-log.md`：Part別ログの索引と、Partをまたぐ構成変更の記録。
- `docs/<part>/ROADMAP.md`：Part内の学習順序・到達条件・現在地。
- `docs/<part>/learning-log.md`：日付ごとの生の感想、疑問、回答、改訂記録。
- `docs/<part>/texts/`：読解用の教材本文。
- `docs/<part>/feedback/`：採点と詳細フィードバック。ログから参照する。
- `docs/<part>/glossary.md`：教材から参照する用語の短い定義と深掘り先。
- `notebooks/<part>/`：答案欄・コードセル・記述回答を一体化した演習提出物。

既存Phase 1〜6は `mechanics` に属する。CAD初稿作成時には `cad` を同じ粒度で新設し、全体の索引へ追加する。
