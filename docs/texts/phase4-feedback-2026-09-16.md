## 演習2：積分は修正済み、入力検証にも同じ契約を適用する

荷重ベクトルの軸の修正と、被積分関数の次数の説明は正しい。提出関数への追加呼出しで以下を確認した。

| Gauss点数 | 剛性成分 k00 [N/mm] | 要素荷重 [N] |
| ---: | ---: | --- |
| 1 | 131250 | [100, 100] |
| 2 | 140000 | [66.6666667, 133.3333333] |
| 3 | 140000 | [66.6666667, 133.3333333] |

ただし `np.any(EA_of_x(points) <= 0)` は、まだ配列を材料関数へ渡す。例えばスカラー入力として有効な `lambda x: 21e6 if x < 100 else 42e6` では、比較結果を一つの真偽値にできずValueErrorになった。積分本体だけでなく、入力検証もスカラー入力という契約を守る必要がある。

修正の方向は、各点で評価したEAの配列を一度だけ作り、その同じ配列について有限性・正値性を確認して積分にも再利用すること。NaNのEAは現状では通過し、NaNの剛性を返す。

`~np.any(np.isfinite(points))` は「有限な点が一つもない」であり、「非有限な点が一つでもある」ではない。意図する一般的な検査は `not np.all(np.isfinite(points))` である。座標自体の有限性も写像前に確認するとよい。これら入力契約・検証をまとめて小問2で2点減点した。

「剛体行列」は「剛性行列」の誤記。数式とテストの意味は通じているため、誤記自体では減点しない。

## 演習4：残差テストは改善、変位と伸びの表記を区別する

自由残差を成分ごとに確認し、全拘束テストも新しいrccを参照するよう修正できている。残差と反力の説明も正しい。追加計算では全拘束の変位 `[0, 0.1, 0]` mm、反力 `[-14000, 24500, -40500]` Nを確認した。

左端を0.1 mmへ変えると、節点変位は `[0.1, 0.3142857, 0.6]` mmとなる。元の解から全成分が0.1 mm増え、伸びは両端差0.5 mmのままである。コードの `d_[-1]-d_[0]` は正しく修正されているが、記述の「結果：変位：変化なし」は「伸び：変化なし」に直す必要がある。応力不変の理由も、全節点の同量の並進により変位差が変わらないため、と明記すると完結する。予測が外れたこと自体ではなく、結果の区別・説明に小問4で1点減点。

不正自由度の明示検査は範囲だけなので、整数型も先に検査すればエラーの理由を伝えやすい。ただし不正な非整数添字は後続の配列アクセスでも例外になるため、ここでは追加減点しない。全拘束の実装と修正テストを確認し、小問2は8/8とした。テストをさらに強くするなら、反力の合計だけでなく既知変位と各反力の期待値も検査する。

## 演習5：誤差積分と収束表は正しい

釣合いと境界条件から解析解を導く説明が追加された。各要素3点で積分し、分子・分母をそれぞれ全要素で足してから比と平方根を取る処理も正しい。提出コードを変更せず実行して以下を確認した。

| 要素数 | 変位相対誤差 | 応力相対誤差 |
| ---: | ---: | ---: |
| 1 | 0.25 | 0.5 |
| 2 | 0.0625 | 0.25 |
| 4 | 0.015625 | 0.125 |
| 8 | 0.00390625 | 0.0625 |
| 16 | 0.0009765625 | 0.03125 |
| 512 | 約9.53675e-7 | 0.0009765625 |

変位次数は約2、応力次数は約1で揃う。512要素では変位次数が約1.9999992となるが、丸め誤差の影響を含む微小な差であり、前回の誤差積分による大きな揺れとは異なる。

考察の「積分点の増加は節点変位の誤差を低減させる」には条件を付ける。積分が不足している場合には改善し得るが、今回の一定EA・一定pの線形棒では1点則でも要素剛性と要素荷重は厳密で、追加点による改善はない。誤差評価用の3点則と、要素行列を作る積分点数も区別する。この例に即した適用条件が不足するため小問4は3/4。場の近似とメッシュ細分化の説明は正しい。

## 採点とは別の改善候補

- 整数型荷重を渡すと、組立は浮動小数点荷重を加算できずエラーになり、求解では `zeros_like(f)` により変位が整数へ切り捨てられる。今回の浮動小数点入力には影響しないが、汎用化するならコピー・変位配列をfloatとして作る。
- 補間関数は依然として右端x=Lを区間に含めない。Gauss点は内部なので今回の誤差積分には影響しないが、右端の変位評価には対応が必要。
- 最初のメッシュには収束次数を定義できない。表の「-」は適切で、グラフも先頭の便宜上の0を除いて描くと誤読を避けられる。
- 前回の大規模時エラーは、今回の1〜512要素の再実行では発生していない。それ以上の失敗条件は今回検証しておらず、原因確定は保留する。
